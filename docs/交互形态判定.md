# 《妹控计划》交互形态判定（第 0 条纪律）

> P0 产物。依据：`docs/交互形态纪律.md`、`docs/无障碍补丁流水线.md` §5.8–§5.9（G61–G77）。
> 判定口径：只看游戏**自己**是否读/写某个东西 —— 不看补丁想不想用。

## 1. 结论

- [ ] A. 游戏已有完全键盘控制 → 补丁只做朗读，不碰输入/焦点/键位
- [x] **B. 有键盘但不完全** → 在游戏自己的输入/焦点层补全（无模式开关）
- [x] **C. 没有键盘控制 / 没有控件模型** → 制造完全键盘控制，但入口仍是游戏自己的动作函数

**结论**：B + C（主体 B）。
剧情主干是 B（游戏硬编码了 Space / 回车 / 小键盘回车 / 滚轮推进、A 自动、F 快进、Ctrl 强快进、R 历史、Esc 返回、P 语音收藏）。
**所有面板是 C**：游戏全工程 0 处 `SetSelectedGameObject`、0 处 `ISelectHandler`/`ISubmitHandler`/`IMoveHandler`、0 处方向键/Tab —— 面板没有任何焦点模型，只能鼠标点。
补法：当前项放进游戏自己场景里预置的 `EventSystem`（**C 类第 2 条「最小选中表示」**，见 §5 遗留缺陷第 1 条），移动/提交走 `Selectable.FindSelectableOn*` 与 `ExecuteEvents.submitHandler → Button.onClick`（与鼠标同一条路），打开/关闭走游戏自己的 `UIManager.OpenUI/CloseOrGoBack`、`PetPanelRegistry.OpenPanel/ClosePanel`。

**判定人 / 日期**：Lead（AI 协作，按 `docs/协作指南-AI开发者.md`）/ 2026-11-11
**证据等级**：反编译实查 + 二进制资源检查（**尚未实机验证新的焦点实现**，见 §4）
- 反编译：`Assembly-CSharp.dll` → 435 个 `.cs`（产物在仓库外 `D:\mk-test\decomp\`，不入库）
- 汇总报告：`INPUT_MODEL_REPORT.md`（同目录，含逐条行号）

补充事实（逐条给证据）：

- **游戏自己的选中态**：没有。`SetSelectedGameObject` / `currentSelectedGameObject` 消费 0 处；`Selectable` 仅 11 处且全是 `transition = Selectable.Transition.None` 或判空；无 `ISubmitHandler`/`IMoveHandler`/`ExecuteEvents`/`Navigation` 赋值。
- **游戏自己的键位表**：有，但只有主干 —— `globalgamemanagers` 里 `Submit`（return/space）、`Cancel`（escape）、`Horizontal`/`Vertical` 四组轴；代码里 28 处 `Input.GetKeyDown`（见 `INPUT_MODEL_REPORT.md` 逐条表）。
- **原生占用键（补丁新增键必须先查这四项）**：Space / 回车 / 小键盘回车 / 鼠标滚轮 = 推进；按住 Ctrl = 强快进；A 自动、F 快进、R 历史、P 语音收藏、Esc 返回/隐藏 UI；`F1` = 游戏自己的开发者测试键（`DialogueV2Runner.cs:314`，按了从开局第一句重播）；`F9` = 调试面板（`DialogueDebugPanelController.cs:15`）。另有 Steam 平台键 F12、读屏器组合键、输入法冲突。
- **界面开/关是否由游戏自己的事件驱动**：是，且收敛得很干净 —— 对话内 14 面板全部经 `UIManager.OpenUI(GameObject, List<GameObject>)`（`:75`）、关闭经 `CloseOrGoBack()`（`:117`）；桌宠 15 面板全部经 `PetPanelRegistry.OpenPanel(string)`（`:154`），并有 `PanelOpened`/`PanelClosed` 事件（`:48`/`:50`）。**不需要扫屏**。
- **公开资料**：只作线索。本项目不使用攻略/旧 wiki 的键位说法作为证据（G76）；键位一律回本机当前版本核对。
- **进入面板后的首焦点**（C② 最小选中表示的落地细节）：按布局取最上/最左的可用控件；若它是
  「关闭/取消/返回」这类一按就离开面板的控件，则顺延到下一个（面板里只有它时才落它）。
  纯图片关闭按钮读不到文字，只用对象名做**分类**（不念给玩家，G72）。
- **滑条的朗读**：左右调值后念「标签：当前值」，值取自 `Slider.value`（整数滑条念整数，
  小数滑条念百分比），不另编进度条语义。
- **首焦点 = 面板自己的「主要分组」**（第二轮起，替代最初的「屏幕最上/最左」）：先落到有语义的
  那组控件，而不是面板角落的装饰/关闭按钮。逐面板见下；选中顺序为
  ①主分组内「首选角色 + 首选标签」→②主分组内首选角色→③主分组内可用项→④主分组内任一项
  →⑤任意组可用项→⑥任意组。面板淡入期间（`CanvasGroup.interactable=false`）不落焦点，
  等 `alpha≥0.99` 且出现可用项再落，最多等 2.5 秒。
- **逐面板主要分组（实机 dump 核对）**：系统设置→显示设置（首焦点「全屏模式」）；换装→服装（「服装7」）；
  音乐列表→曲目（「OP-透明的她(中文版)」）；背景设置→环境音效（「仲夏虫吟」）；收藏内容→页签（「主线」）；
  番茄钟→时长（首选输入框「专注时长」，内容 25）；日程表→任务（「新建任务」）；鬼畜制造机→工程列表（「工程 1」）；
  联动展架→作品（「透明的她与真实的我」）；今天吃啥→推荐方式（「随机推荐」）。
- **分组与序号**：每个控件都带「分组 + 第 N 项，共 M 项」，分组名与游戏界面上的标题一致
  （显示设置 / 桌宠设置 / 音量设置…，见 `PanelMap.SectionOf`）。控件少于 3 项时不报序号，
  避免「共 1 项」这类噪声。
- **无字控件的标签**：除按游戏字段/路径映射（`UiNav.Game.cs`）外，新增「邻近文本关联」——
  取同一行左侧或正上方的短文本（≤12 字）作为输入框/滑条的标签，解决番茄钟三个输入框
  原本只念「000」的问题；关联不到才退回「按钮/输入框」+ 位置。
- **不可用项**：未解锁/禁用的控件不进首焦点，但**仍可用方向键访问**，朗读里报「当前不可用」，
  玩家不会「听得到却按不动而不知道为什么」。
- **长列表**：Home 跳首项、End 跳末项、PageUp 上移 5 项、PageDown 下移 5 项
  （反编译核对：游戏自身 0 处占用这四个键）。
- **动作后内容重建**：回车可能让列表换页（收藏内容：章节 → 节列表），原选中项失效时自动
  落到新列表第一项，并只播报新增的可用项（「现在可以：…」），不整表重念。
- **剧情进行中不接管**：`Reader.InDialogue` 为真时不进入任何焦点域；若游戏存在对话操作栏，
  剧情域只接主回车，空格/小键盘回车留给游戏推进剧情。
- **纯图片按钮的约定动作名**（第二轮覆盖审计补）：关闭 X、唱片机五个媒体键在游戏里既没有
  TMP 文本，也没有本地化条目，旁边的文字属于别的控件（关闭 X 曾被念成面板标题「系统设置」
  「特别」）。补丁按**游戏自己的对象名**给出约定动作名：`CommonCloseButton`→关闭、
  `已完成界面按钮`→已完成的任务、`VolumeButton`→音量、`Pre`→上一首、`Play/Pause`→播放或暂停、
  `Next`→下一首、`PlayMode`→播放模式；只表达「这个动作叫什么」，不把对象名当玩家语义（G72）。
- **媒体条按钮的父子关系**：主界面唱片机 5 个按钮是进度滑条 `PetMusicPlayer_Window/Slider` 的
  子节点，不是重复包装。控件去重只在「父控件世界矩形完整盖住子控件且面积比 ≥0.5」时丢子控件，
  滑条/开关的子控件永不丢——否则 5 个媒体键会被整组吞掉（主界面只剩 13 项）。
- **语音收藏的入口**：`PetUiIntegrationHub.OpenVoiceCollect()` 走
  `PetPanelRegistry.PresentOpen(GameObject)`，**不经过** `OpenPanel(string)`；焦点层因此额外挂
  `PresentOpen`/`PresentClosed` 两个挂载点（面板 id 由根节点名经 `PanelMap.KeyOf` 反查），
  否则整个面板进不去焦点。
- **提示框 / 确认框：正文要单独念，标题用短名**（第二十轮）：`Tips1`/`Tips2` 的正文
  （「该功能当前还在开发中，请哥哥以后再来探索吧」「哥哥确认要删掉它嘛？」）画在面板自己身上，
  不是任何控件的标签；旧实现把它当标题回退出来，结果正文和按钮名（「好的 / 不好也得好」
  「犹豫一下 / 当断则断」）混在一句里。现在固定短标题（提示 / 确认删除），正文单独念，
  且**排除按钮上的字**（`ContentText(..., excludeSelectable: true)`）；纯中文句子去掉换行空格，
  避免怪断句（`Focus.TryFocusFirst` / `ContentText` / `PanelMap.HasBody`）。
- **剧情进行中按 F2 要报「正在剧情中」**（第二十二轮）：剧情里焦点层没有域，旧实现会落进
  「当前没有打开的面板」并把玩家引向方向键；现在先判 `Reader.InStory`，播「正在剧情中：
  回车或空格继续，遇到选项用方向键选、数字键确认。」，有面板时追加「面板：…」
  （`Surfaces.ReportState`）。
- **联动展架的依赖链要按游戏自己的三层走**（第二十六轮）：作品卡（`GameSlot`）按下是切面板内的
  二级页 `SceondPanel1`（作品名 + 「游戏简介：」+ 三个社交链接），不是打开外链；二级页里的
  `CollabExternalLinkButton` 才走 `Application.OpenURL` / `steam://store/<appId>`，会把画面切出游戏。
  三个链接的 TMP 文本都写「社交链接」，用 `PanelMap.LabelOverride` 按对象名区分（Steam 商店页 /
  小黑盒 / Bilibili 视频）；激活外部链接时补一句「画面会切出游戏。回来以后按 Esc 关面板」，
  否则玩家会以为补丁崩了。`Focus.ActivateCurrent` 用在提交前取 `CollabExternalLinkButton`
  组件的方式判类型，不按标签猜。
- **F1 菜单不是「模式」，是同一批控件的第二种走法**（第三十二轮，回应用户 m04680「两类玩家」）：
  菜单里的 12 项与主界面 `Right`/`UpRight` 上的 12 个图标一一对应，不用菜单也能用方向键走到
  同一个图标按回车（`Kind.Scene` 域）。菜单本身是补丁维护的**最小选中表示**（C② 允许），
  上下走列表、左右翻页、回车激活、Esc 关闭，和游戏自己的列表同一个手感；数字键只是加速器，
  不在播报里教学。没有模式开关、没有专属按键之外的新元操作。
- **播报文案只说事实，不解释玩法**（第三十一轮）：用户听完第一轮实机后要求收紧文案——
  解释写进代码注释，不念给玩家。落地：启动提示只报 F1/F2/退格/F5 四个键；面板提示一律一句
  （设置、换装、番茄钟、收藏、日程、联动展架保留必要依赖，其余清空）；外链只念「已打开「X」。」；
  桌宠模式只念「F5 切回全屏」；小游戏开局只报棋盘大小和脚下这张、局末只报比分；
  剧情中 F2 只报「剧情中。」；`Focus.Describe` 不再每项念「按钮」，「共 M 项」只在换分组时念。
- **覆盖审计**（2026-11-11 第二轮，仓外 `D:\mk-test\audit\COVERAGE_AUDIT.md`）：把运行时真实
  可操作控件与焦点层给出的项逐面板对照。审计后项数为主界面 18、系统设置 9、日程表 3、
  番茄钟 11、今天吃啥 3、音乐列表 30、换装 16、背景设置 19、收藏内容 6（切页签 20）、
  鬼畜制造机 168（工程列表/素材搜索/轨道编辑等 6 个分组）、联动展架 5、语音收藏 1。未覆盖：
  追番助手（游戏只有 prefab、无控制器）、语音收藏条目（运行时生成，本存档 0 条）、
  剧情独立场景的 14 个面板（见 §5）。
- **动作结果要说回来**（第四轮，2026-11-11）：游戏对这些控件本身不回话（开关不报开/关、
  点歌不报开始播放、换装卡换了一张也不报），读屏用户会以为按键没生效。补丁在回车后
  0.5 秒按**同一个控件**复检：状态变了念「名称，已开启/已关闭」或「名称，55%」；
  同一控件显示内容换了（换装卡车轮播 服装7→服装6）就把当前这张念清楚，**不**念
  「现在可以：服装6」（那会让人以为凭空多出一件）；音乐列表点曲目后读游戏自己的
  `PetMusicScrollListController.CurrentEntry.displayName`，对得上才念「正在播放：曲名」，
  读不到就不念（不猜）。
- **列表行里的标记开关不算独立项**（第四轮）：音乐列表每行是「行按钮（曲名）+ 行内
  `CommonToggle`（指示当前曲目）」，开关没有自己的可读文字；判据限定为「Toggle 且是另一个
  Button 候选的后代」才丢弃，设置/番茄钟/背景里那些真正的开关不受影响。
- **行内嵌套的装饰按钮不算独立项**（第四轮）：按钮内部的图标也可能挂 Button
  （`musicButtons/导入音乐/Image`），判据限定为「不可交互 且 是可交互 Button 的后代」才丢弃。
- **名字画在槽位里的开关**（第四轮）：背景设置的环境音效槽是「名字 + 开关 + 滑条」，
  名字是槽里的独立文本节点、不在开关之下。父节点借文本的规则因此放宽为
  「父节点不是焦点域根 且 该父节点下控件 ≤ 4」——域根仍一律不借，关闭按钮不会被念成
  面板标题（第一轮的串词缺陷就是域根借文本造成的）。

- **桌宠待机台词不算「在过剧情」**（第五轮，2026-11-12）：桌宠的 idle 台词（`basic_待机_*` /
  `basic_启动_*` / `basic_点击_*` / `basic_作息_*` 等）也会走 `NotifyScenarioStarted`，但玩家此刻
  仍然在主界面上。焦点层因此不用 `InDialogue` 布尔判断「要不要退出主界面浏览」，改用
  `Reader.InStory`（场景 id 不是 `basic_` 前缀才算剧情）。否则一按方向键进主界面，下一句待机台词
  就把浏览域踢掉，玩家会感觉「方向键时灵时不灵」。
- **系统设置没有「应用」这一步**（2026-11-12 核对）：`WindowModeSettings.cs` 的
  `OnWindowModeToggled` / `OnFullscreenModeToggled` / `OnResolutionToggled` 内部直接调
  `ApplyWindowMode()` / `ApplyFullscreenMode()` / `ApplyResolution()`，音量走
  `PetSettingsApplier.Apply*Volume` —— **改完立刻生效**；`桌宠大小` 滑条由
  `RefreshDeskPetScaleSliderInteractable()` 按「当前是否桌宠模式」实时切 `interactable`。
  prefab 里那两个「应用」「还原」按钮运行时一直 `active=0`、实测从未出现，属未启用残留，
  所以补丁的提示语不能写「按应用才生效」（第五～七轮的实测与反编译都指向即时生效）。

- **输入框靠补丁「代打」+ 结束输入时补发 `onEndEdit`**（第十二轮，2026-11-12）：本作所有输入框
  都只靠鼠标点进去（唯一焦点代码 `AutoFocusInputField.cs:12` 的 `Select()` + `ActivateInputField()`）。
  补丁自己调 `Select()`/`ActivateInputField()` 之后，TMP 的事件队列收不到注入键（`Input.inputString`
  有字符但 `text` 一直空），而「先激活再补打」会重复（`ABC23ABC23`）。最终做法：
  `EventSystem.current.SetSelectedGameObject(f.gameObject)` + `f.Select()`（**不调 `ActivateInputField`**），
  键入由补丁从 `Input.inputString` 累积后写入 `f.text` 并逐字回声；因为没走 TMP 自己的激活路径，
  游戏收不到 `OnEndEdit`，所以 `EndEditing` 里主动 `f.onEndEdit.Invoke(txt)`。
  实测：清空面板再打开，`TaskDescription` 仍保留输入内容（游戏侧已收到），中文（`买菜`）可写入。
  遗留：`Input.imeCompositionMode` 已复位为 `Auto`，中文经 `inputString` 提交，输入法候选窗/
  组字过程中的回显未在真机核对（登记在 §5）。

- **输入框的类型约束要由补丁替游戏挡，非法字符要说明；搜索框要报结果数**（第十三轮，2026-11-12）：
  番茄钟三个时长输入框在 prefab 里是 `contentType=Standard` + `characterValidation=None`（TMP 层
  什么都不挡），但游戏读值走 `int.TryParse`（`PomodoroManager.SetFocusMinutesFromString` /
  `SetRestMinutesFromString` / `SetCycleCountFromString`）——写进字母会被**静默丢弃**，玩家会以为
  改成功了。补丁因此按 `PanelMap.NumericInput(key, section)`（pomodoro + 时长设置）只放数字，
  并播「这个输入框只能输数字，其它字符已被忽略。」。
  音乐列表的搜索框会随输入实时过滤曲目（`onValueChanged` 由 `f.text` 赋值触发），补丁在项数变化时
  播「现在共 N 项。」/「没有符合条件的项。」——否则盲人打完字不知道到底筛出东西没有。

- **播放控制要读游戏自己的播放状态来说结果**（第十四轮，2026-11-12）：主界面唱片机的
  `播放或暂停 / 上一首 / 下一首 / 随机 / 播放模式` 与音乐列表底部同名按钮，游戏按下去只换图标，
  没有任何声音。补丁按「玩家按的是哪个动作」去读游戏字段确认：`IsSourcePlaying`
  （`PetMusicScrollListController.IsSourcePlaying` → `AudiosPlayer.Instance.bgmSource.isPlaying`）
  决定「正在播放：曲名。」还是「已暂停。」；`CurrentEntry.displayName` 给出换到哪首；
  `PlayMode`（`PetMusicPlayMode`）给出「列表循环 / 单曲循环 / 随机播放」。读不到就不播，绝不猜。
- **播完自动换歌靠只读镜像播报**（第十四轮）：`Focus.Tick` 里 0.5 秒节流地比对
  `CurrentEntry.displayName`，只在主界面或音乐面板里做，进门时把当前曲目记成基线（打开面板不额外念）。
  这处**只读游戏状态、不接管任何输入、不改游戏字段**，因此与纪律里禁止的「用轮询代替游戏事件」
  （G71，指输入路径）不同：播报只是镜像，玩家按键仍然走游戏自己的入口。判定与依据登记在此。
- **主界面进度条标签是「播放进度」**（第十四轮）：`PetMusicPlayer_Window/Slider` 子树里的文字是
  曲名（属于曲目按钮），滑条本身表达播放位置，所以标签不从子树借文本，直接给「播放进度」+ 百分比。
  同一路径规则会被「音量」按钮展开的 `VolumeButton/Common_HSlider` 误套（两条滑条撞名，按「音量」
  后新增项因重名播不出来），所以那条单独认成「音乐音量」——实测「现在可以：音乐音量。」，
  方向键调值念「音乐音量，滑条，60%」→「55%」。
- **换页之后焦点要落到新列表上**（第十五轮）：收藏内容里点章节，游戏把章节卡换成「第1节…第17节」，
  原来的章节卡失效。此时若按「打开面板时的主要分组」规则回页签，播报还是「当前：主线」，
  玩家会以为回车没生效。规则改为：原项失效 → 先按刚激活的标签找回 → 再落到**内容最多的那一组**
  的第一项（≥2 项才算一组）并说「已进入章节，第1节，共 20 项。」；新项常晚一帧才 enable，
  初始化期**不念「当前不可用」**，2 秒内每 0.3 秒补查一次、可用后静默补定位
  （实现：`Focus.AnnounceNewItems` / `LargestSectionIndex` / `_sectionRetry*`）。
  注意「场景 → 章节」会关掉面板进入剧情（`story_1_初见`），属游戏正常行为，不是焦点丢失。
- **面板只改文字、不加控件时，也要把新字说出来**（第十六轮）：`今天吃啥` 点「随机推荐」只更新菜品名
  和「本轮推荐：X」，控件数量一个都没变，旧逻辑因「原选中项还在」提前 return 而一声不吭。
  做法：动作前记下列表之外的可见说明文字（`Focus.InfoTexts()`：可见、alpha≥0.05、非占位、
  1–40 字、不嵌在 `Selectable` 里），0.5 秒后比差异播「现在显示：…」。被别的条包含的短条去掉
  （「回锅肉」被「本轮推荐：回锅肉」包含，只念后者），画在菜品图上的「图片占位」按占位字过滤；
  只播新增的字，不猜结果语义（G72）。文字播完、原按钮还在原地时静默收回选中项，避免重复念一遍。
- **剧情盖在面板上时，按键归游戏**（第十七轮）：tool 剧情（`tool_番茄钟_启动`、`tool_日程_完成_2`）
  会在面板不关的情况下播（实测 `state` 仍「日程表（PetPanel）共 3 项」）。此时①补丁不能再把
  回车/空格当「激活控件」（会误触面板按钮），②`Patches.DialogueAdvanceGate` 不能再拦游戏自己的
  `DialogueSceneManager.DialogueButtonClicked`（否则剧情推不动）。做法：`HandleKeys()` 首行
  `if (Reader.InStory) return false;`、`DialogueAdvanceGate.Pre()` 里 `if (Reader.InStory) return true;`；
  剧情结束后 `Focus.Tick()` 用 `_storyWasActive` 检测收尾，补播「回到 <面板>，当前：…」，
  否则玩家听完台词就丢了上下文（依据：`ShiMeng.DialogueV2` 剧本触发器 `DialogueTriggerCategory.Tool`）。

## 3. 反模式自查

- **「隐藏界面」在游戏里是单向的**（第十轮，2026-11-12）：`PetUiIntegrationHub.ToggleHideAllUiRoots()`
  调 `HideAllUiRoots(waitForLeftClickToRestore: false)`，之后唯一的恢复路径是
  `RestoreAllUiRoots()`（按钮自己被藏起来了，左键恢复也被 `false` 关掉），游戏没有 Esc 恢复。
  补丁在 `F1` 菜单发现「所有入口按钮都不可见」时改调 `RestoreAllUiRoots()`，播报
  「界面已恢复显示。按方向键可以浏览主界面。」；恢复失败才提示用鼠标左键点一下屏幕。
  依据：`proj/PetUiIntegrationHub.cs` L280-289（`_restoreOnLeftClick` 门）、L352/L374/L383。
- **「退出游戏」游戏侧没有确认框**（第十轮）：`PetUiIntegrationHub.QuitGame()` →
  `DialogueEntryManager.RequestGracefulQuit()` → `CoGracefulQuit()` 播完告别对话直接
  `Application.Quit()`（`proj/ShiMeng.DialogueV2/DialogueEntryManager.cs`）。键盘一个数字就能
  关掉进程，所以补丁在菜单层要求「同一个数字键 5 秒内按两次」（配置 `CfgQuitConfirm`，默认开）；
  等待期间菜单保持可用，选别的项即取消；确认后播「正在退出游戏。」。

- **小游戏打完一局之后，方向键必须交回面板**（第十一轮，2026-11-12）：游戏侧 `EndGameCoroutine()`

  `MemoryMatchGameController.IsGameRunning`：一局结束就播「小游戏结束。哥哥 X 分，诗萌 Y 分。
  你赢了/诗萌赢了/平局。」并把方向键交回焦点层，关闭按钮立刻可达。
  依据：`proj/ShiMeng.Minigames.MemoryMatch/MemoryMatchFlowOrchestrator.cs`（`EndGameCoroutine`、
  `StopGame`）、`MemoryMatchGameController.cs`（`IsGameRunning`、`OnGameEnded`）。
