# 《妹控计划》操作约定（逐作填写）

> 依据：`docs/操作逻辑公约.md`（Framework 0.2.7.3 起）。
> **P0 起草、P3 定稿、P4 用测试问卷核对。**
> 只写本作的实际值；与公约默认不同的每一处都要给原因，不许只写「游戏不同」。

本作当前阶段：**P4（2026-11-12，0.2.1.0）**。用户在本版明确裁决的保留项（位置计数、`Backspace` 重读）记在 §2 与本文件末尾的变更记录里。

## 1. 采用情况

- 交互形态判定：□ A ☑ B ☑ C（B + C，主体 B；结论与逐界面证据见 `docs/交互形态判定.md` §1）
- 界面键盘来源：**补全 + 制造**（游戏没有任何焦点模型：全工程 0 处 `SetSelectedGameObject`、
  0 处 `currentSelectedGameObject` 消费、0 处 `ISubmitHandler`、0 处方向键 —— 见
  `D:\mk-test\decomp\INPUT_MODEL_REPORT.md`，仓外证据。补丁补的是「读方向键 + 让游戏自己的
  `Selectable` 获得选中态」这一层，实际入口是 `Focus.HandleKeys()`）
- 激活级别（公约 §2）：**1 与 2 混用**（逐界面见 §3）
  - 第 1 级（直接调游戏的动作方法/字段）：小游戏 `OnCardClicked(int)`、诗萌身体 `Pet.Poke()`、
    「和诗萌聊聊」气泡 `MainStoryTriggerButtonVariant` 的 `Button.onClick`、文本输入框
    `TMP_InputField.text` 写入 + `onEndEdit.Invoke`、隐藏界面恢复（反射调游戏自己的
    `RestoreAllUiRoots()`）
  - 第 2 级（走游戏自己的 Unity UI 事件链）：所有 `Button` / `Toggle` / `Slider` / `TMP_InputField`
    的显式激活一律 `ExecuteEvents.Execute(..., submitHandler)` —— 与鼠标点击走同一条 Press 路径，
    不伪造 OS 输入、不直接 `onClick.Invoke()` 绕过可用性判断（唯一例外是「和诗萌聊聊」气泡，
    原因是它的 `onClick` 是游戏自己挂的、没有 `Selectable` 可提交；见 §3）
  - 第 3 级（只读扫描 + 编号）：**未使用**
- 是否使用遗留导航模式：☑ **否（默认）**。`CfgMenuNav` 默认 `false`，`UiNav.cs` 只在玩家手动打开该
  遗留开关时才运行；默认路径完全不经过它。

## 4. 焦点、朗读与撤销

- 进入页面时初始焦点由谁设置：**补丁**（`Focus.TryFocusFirst()` → `EventSystem.SetSelectedGameObject`），
  因为游戏从不设初始焦点；首焦点规则（主要分组 + 首选标签 → 非关闭类 → 任意可用）写在
  `docs/交互形态判定.md` §2。
- 是否抑制程序化焦点造成的重复播报：☑ 是（补丁自己设完焦点后直接播报一次，不另监听 EventSystem
  的 `selectionChanged`，避免同一项念两遍；`AnnounceNewItems` 还带 0.1 s 去抖与同文去重）。
- 离开页面时焦点恢复方式：面板关闭走游戏自己的 `ClosePanel`/`CloseOrGoBack`，补丁在
  `UIManager.CloseOrGoBack` 的 postfix 里把焦点交还 `uiStack.Peek()`（游戏自己的栈），
  清空选中则 `SetSelectedGameObject(null)`。
- 延迟朗读的取消条件：`Announcer` 队列在页面切换/新播报到达时丢弃过期项；动作后重聚焦窗口
  `_afterActionAt`（0.5 s）与换页补落 `_sectionRetry*`（2 s 内每 0.3 s）都有超时上限。
- 输入订阅 / 事件订阅 / 焦点恢复在页面销毁时是否撤销：☑ 是（`Plugin.OnDestroy → Shutdown()`：
  `Speech.Shutdown()` + `_harmony.UnpatchSelf()` + `A11yHost.Clear()`；`Focus.Leave()` 清域与选中）。
